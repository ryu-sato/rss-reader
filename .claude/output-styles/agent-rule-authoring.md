`.claude/rules/` 配下のファイル（エージェントルール）を新規作成・編集するときは、以下の規約に従う。適用条件は EARS 形式で記述し、ルールの管理と背景には USDM（Universal Specification Describing Manner）を適用する。

## ファイル構造

1 ファイル 1 ルール。ファイル名は `kebab-case.md`。以下の 4 部構成とし、セクションを増やさない。

```markdown
---
description: <一行説明>
paths:                        # トリガーがファイルの作成・編集に限られる場合のみ
  - "<対象ファイルのグロブ>"
---
# RULE-<slug>: <何をするかを命令形で書いた見出し>

## 背景・理由
なぜこのルールが必要か。守らなかったときに何が起きるか。

## 適用条件
- <slug>-1: When <トリガー>, the Agent shall <動作>.
- <slug>-2: If <望まない状況>, then the Agent shall <動作>.

## 管理
- 単一の情報源: `<参照先パス>`
- 独立ファイルの理由: <なぜ CLAUDE.md や steering ではなくここに置くのか>
```

`<slug>` はファイル名（拡張子なし）と一致させる。`paths` は任意であり、省略した場合そのルールは毎セッション無条件にロードされる。

## 適用条件 — EARS 形式

条件は `.claude/skills/kiro-spec-requirements/rules/ears-format.md` の EARS パターンに従って書く。同ファイルを単一の情報源とし、パターンの定義をここに転記しない。ルールファイル固有の適用方法は次の通り。

- **主語は `the Agent` で固定する。** ルールが規定するのはエージェントの振る舞いであり、システムの機能ではない。`the System` や `the Rule` を主語にすると条件が意味をなさなくなる。
- **トリガー語と固定句は英語のまま書く。** `When` / `If` / `While` / `Where` / `then` / `the Agent shall` を英語で保ち、可変部（トリガー・状態・動作）だけを日本語で書く。固定句の内部に日本語を混ぜない。
- **条件は発火点で書く。** 「〜を実行しようとする」「〜を変更しようとする」のように、エージェントが行動に着手する瞬間を捉える。事後の状態を条件にしない。
- **抜け道は `Where` で明示的に塞ぐ。** 例外だと解釈されそうな経路（`/kiro-*` 経由など）を条件として書き出し、同じ動作が適用されることを述べる。
- **1 条件 1 振る舞い。** 複数の動作が必要なら条件を分割する。検証できない条件は書かない。
- **対象は実物で列挙する。** 「インフラ系コマンド」で終わらせず、`kubectl` / `helm` / `helmfile` / `argocd` のように具体名を挙げる。
- **対象ファイル範囲が `paths` で表現できる場合は frontmatter に委譲する。** その場合は条件のトリガーで対象ディレクトリやファイル種別を繰り返さない。ただしコマンド実行のようにファイルの Read で発火しないトリガーを含むルールには `paths` を付けない — 付けるとルール全体がそのグロブにゲートされ、そのトリガーの瞬間にロードされなくなる。

## 背景・管理 — USDM

USDM の適用範囲は次の 3 点に限る。表形式にはせず、上記の Markdown 見出し構造で表現する。

- **理由を必須にする。** すべてのルールは「背景・理由」を持つ。条件だけを書いたルールは不完全とみなす。理由は「なぜ必要か」と「守らなかったときに何が起きるか」の両方を含める。
- **階層 ID を振る。** ルール本体を `RULE-<slug>`、その下位の適用条件を `<slug>-1`, `<slug>-2` … とする。ID は条件の参照・議論・変更追跡の単位であり、条件を削除しても既存 ID を再利用しない。
- **変更は ID 単位で行う。** 条件を追加・変更・削除するときは、どの ID が変わったかを説明できる形で編集する。条件を丸ごと書き換えて ID の対応を失わせない。

## 情報源を転記しない

ルールの本体が他のドキュメントにある場合、その内容をルールファイルに写さない。「管理」セクションで参照先を単一の情報源として示し、そこから辿るべきファイルを条件側（`If <情報が不足する>, then the Agent shall <参照先を辿る>.`）に書く。二重管理を避けることがこのリポジトリで最も重視される点である。

同じ理由で、ルールの内容を `CLAUDE.md` に転記しない。`CLAUDE.md` は cc-sdd が生成・更新するファイルであり、上書きで失われる。

## 文体

日本語で書く。技術用語・コード識別子・コマンド・パスは原語のまま `バックティック` で囲む。断定的な命令形で書き、「〜するとよい」「可能であれば」は実際に任意である場合にだけ使う。見出しは命令形の平叙文とし、疑問形・体言止め・「〜について」は使わない。エージェントが毎セッション読むファイルなので、長いほど守られなくなる — 短さを優先する。
